# text-db-query-ai 0.1.0: design

Status: accepted, 2026-10-26. Target: `0.1.0`, a backwards-compatible release.

## 1. Why

0.0.1 has security holes that normal use can reach. It also rejects ordinary queries, and its default Claude model no longer exists.

- **Stacked statements pass validation.** `sanitize()` strips a trailing `;` before it normalizes whitespace. Model output `SELECT id FROM t; DELETE FROM t; -- done` therefore validates as a single SELECT, and raw `pg` would run the DELETE.
- **Row-level security leaks and can be injected.** `WHERE a OR b` with an appended `AND user_id = 5` returns other users' rows. The filter is inserted after `GROUP BY`. String ids are interpolated without escaping. The filter is skipped whenever any `WHERE ... user_id` exists, so `WHERE user_id = 999` bypasses it.
- **The substring regexes cause both "hallucination" failures the maintainer reported.**
  - Ordinary names are rejected as SQL commands: `created_at` is read as CREATE, `grants` as GRANT, `'dropped'` as DROP, `executed_at` as EXEC. `password` also blocks `password_updated_at`.
  - At the same time, dangerous queries pass: `pg_sleep`, `pg_read_file`, `INTO OUTFILE`, `load_extension`, `dblink`, `set_config`, `SELECT ... INTO`, and comma-join table bypasses (`FROM allowed, secret`).
- **The model invents tables and columns, and nothing checks for it.** The schema it sees is often wrong too:
  - MySQL 8 introspection returns nameless tables (uppercase column labels).
  - SQLite crashes on reserved table names.
  - `parsePrismaSchema` emits columns such as `unique`.
  - Postgres mixed-case tables (Prisma's `"User"`) are shown unquoted, so the model writes `FROM User`, which fails.
- **Providers are out of date.**
  - `claude-3-5-sonnet-20241022` was retired on 2025-10-28.
  - `temperature` is rejected by the current Claude API.
  - `gpt-4o-mini` shuts down 2027-01-14.
  - Current OpenAI reasoning models reject `max_tokens`, and reject `temperature` unless reasoning effort is `none`.
- **Publishing is broken.** npm revoked classic tokens, and the publish workflow uses removed Node 20 actions.

## 2. Goals, non-goals, anti-goals

**Goals**
1. Close the security holes above.
2. Stop rejecting valid SQL because of words inside names or strings.
3. Reduce invented identifiers. To do that: give the model an accurate, dialect-correct schema; check the generated SQL against it; ask the model to correct itself once.
4. Update models and SDKs, and make the package work on Node 18 through 26.
5. Make introspection efficient: a constant number of queries, not N+1.
6. Fix the docs, CI and the OIDC publish workflow.

**Non-goals (this release)**
- MongoDB.
- The Responses API.
- Structured JSON output.
- An optional WASM SQL parser.
- Schema pruning.
- An OpenTelemetry integration.
- ESM `exports` maps.
- openai v7, which needs Node 22 (deferred to a major release).

**Anti-goals (a failure even if everything else works)**
- Any 0.0.1 public symbol, method or constructor signature is removed or changes meaning.
- A query 0.0.1 accepted is now rejected, unless it is clearly dangerous. Every such case must be listed in the CHANGELOG.
- A new error is thrown on a path that used to succeed. Opt-in modes (`identifierCheck: 'strict'`, `enforceSensitiveColumns`) are the only exception.
- `result.query` changes for queries that need no security fix, beyond whitespace normalization.
- Data the user did not opt into (DB error text, sample rows) is sent to the LLM.

## 3. Compatibility contract

- **Exports.** Every export of 0.0.1 stays, with the same kind (class, function or object). The default export keeps its keys.
- **Error codes.** These stay as they are: `OPENAI_API_ERROR`, `OPENAI_EMPTY_RESPONSE`, `CLAUDE_API_ERROR`, `CLAUDE_INVALID_RESPONSE`, `INVALID_SQL_SYNTAX`, `SECURITY_VALIDATION_FAILED`, `QUERY_GENERATION_FAILED`, `UNSUPPORTED_PROVIDER`.
  - New failure kinds (refusal, token limit, abstention) reuse the nearest existing code and set fields on `details`.
  - The only new codes are for opt-in modes: `UNKNOWN_IDENTIFIERS`, raised only by `identifierCheck: 'strict'`.
- **`SecurityValidator`.**
  - `validate(query, userContext?)` keeps returning `{valid, errors, warnings}`.
  - Existing error strings keep their wording: "Multiple statements detected", "Could not determine query operation", "Operation X is not allowed…", "Query contains dangerous patterns: …", "Query accesses restricted columns: …", "Query accesses unauthorized tables: …", "LIMIT n exceeds maximum…", "User context is required but not provided", "Custom validation failed".
  - The constructor gains an optional second argument `SecurityValidatorOptions {databaseType?, schema?}`.
- **`QuerySanitizer`.**
  - `new QuerySanitizer()` still works.
  - The constructor gains an optional `databaseType`.
  - Method signatures stay. `enforceLimit(query, limit)` is added.
- **`BaseLLMProvider`.** New methods are concrete and have defaults: `generateWithSystem(system, prompt)`.
- **`SchemaAnalyzer.generateSchemaPrompt()` and `QueryGenerator.getSchema()`.** For schemas that use no new fields, the output stays byte-identical. The richer, dialect-quoted rendering the model sees is a separate method.
- **RLS output.** Single-table queries produce the same text as 0.0.1 (` WHERE user_id = 123`, or `… AND user_id = 123`). Parentheses are added only when the existing condition has a top-level `OR`.
- **Types.** Public `.d.ts` files never expose SDK types. All new config fields are optional.
- **Defaults kept.** `allowedOperations: ['SELECT']`, `requireUserContext: true`, `enableRowLevelSecurity` defaulting to true in the validator, `maxRowLimit` 1000 in the validator, and UNION blocked.

## 4. Decisions

| Topic | Decision | Why |
|---|---|---|
| Version | `0.1.0` | `^0.0.1` pins exactly 0.0.1, so nobody upgrades by accident. A minor bump signals the new features. |
| Node | `engines >=18` | 0.0.1 already fails on Node 16 (no global `fetch`). 18 is the real floor. |
| openai | `^6.49.0`, loaded lazily | v7's only breaking change is Node ≥22. The calls we use are identical on 6.x and 7.x. |
| @anthropic-ai/sdk | `^1.3.0`, loaded lazily | Current API version. `temperature` is removed from requests. The license is now Apache-2.0, recorded in NOTICE. |
| Claude default | `claude-opus-5-5` | The current flagship. Sonnet 5.5 and Haiku 5.5 are documented as cheaper choices. |
| Claude requests | No `temperature` and no `thinking` param. `max_tokens` defaults to 16000, streamed with `finalMessage()`. `fallbacks: 'default'` (beta `server-side-fallback-2026-07-01`) is on unless `baseURL` is set or `fallbacks: false`. The system prompt is cached. | Thinking is always on for Opus 5.5. Fallbacks keep classifier false positives from becoming outages. |
| OpenAI default | `gpt-6-luna` | OpenAI's named replacement for gpt-4o-mini, and cheaper. |
| OpenAI requests | `max_completion_tokens` on api.openai.com, `max_tokens` when `baseURL` is set. `temperature` only for non-reasoning models, custom endpoints or `reasoningEffort:'none'`. One automatic retry that drops a parameter the server reports as `unsupported_parameter`. `maxTokens` defaults to 8192. | Reasoning models reject the old parameters. Compatible endpoints differ. |
| Parser | A zero-dependency, dialect-aware lexer (`src/sql`) | node-sql-parser is 92 MB and wrongly rejects 7.5% of valid queries. The prototype lexer rejected none of 159 valid queries and blocked 38 of 39 dangerous ones. |
| Identifier check | Default `'retry'` with `maxCorrectionAttempts: 1`. If issues remain, the query is returned with warnings. | This reduces invented names without ever throwing anew. |
| Abstention | The prompt allows `CANNOT_ANSWER: <reason>`, which is thrown as `INVALID_SQL_SYNTAX` with `details.cannotAnswer = true`. | Prose output was already `INVALID_SQL_SYNTAX` in 0.0.1. |
| Sensitive columns | Warn by default; reject with `enforceSensitiveColumns: true`. `restrictedColumns` are enforced, including through `*`, `t.*` and `row_to_json(t)` when a schema is known. | Restricted columns are a security setting. Sensitive columns are a hint. |
| Execution repair (ChatbotHelper) | Opt-in (`repairAttempts`, default 0) | It sends DB error text to the LLM. |
| Peer deps | Widen to `>=` the current majors. Drop the `prisma` CLI peer. | The package never imports them, and the old ranges blocked Prisma 6/7 and sqlite3 6. |

## 5. Architecture

### 5.1 `src/sql` contract (everyone depends on this)

```ts
export type SqlDialect = 'postgres' | 'mysql' | 'sqlite' | 'mssql' | 'generic';
export function toSqlDialect(t?: DatabaseType): SqlDialect;            // mongodb/undefined -> generic
export type TokenType = 'word' | 'quoted' | 'string' | 'number' | 'param'
                      | 'operator' | 'punct' | 'comment' | 'whitespace';
export interface Token {
  type: TokenType;
  text: string;   // exact source slice
  value: string;  // word: UPPERCASED; quoted: unescaped identifier name (case kept); else = text
  start: number;  // offset in source, inclusive
  end: number;    // offset in source, exclusive
}
export class SqlLexError extends Error {
  kind: 'unterminated_string' | 'unterminated_quoted_identifier' | 'unterminated_comment';
  position: number;
}
export interface LexOptions { backslashEscapes?: boolean } // MySQL only; default true
export function tokenize(sql: string, dialect?: SqlDialect, options?: LexOptions): Token[];
```

**Lexing rules**
- **Strings.**
  - Single-quoted strings with `''` escapes.
  - Postgres `E'…'` strings use backslash escapes. Plain `'…'` strings do not (standard_conforming_strings).
  - Postgres dollar quoting (`$$…$$`, `$tag$…$tag$`).
  - MySQL `'…'` and `"…"` strings (`"` is a string in MySQL), with backslash escapes unless `backslashEscapes:false`.
  - `N'…'`, `X'…'` and `B'…'` prefixes.
- **Quoted identifiers.** `"…"` everywhere except MySQL; backticks in mysql, sqlite and generic; `[…]` in mssql and sqlite.
- **Comments.**
  - `--` comments, plus MySQL `#`.
  - Block comments `/* */`, nested in Postgres.
  - MySQL `/*! … */` is a comment token. The validator treats any comment as dangerous.
- **Params.** `$1`, `?`, `:name`, `@name` (MSSQL `@@x` too).
- **Operators.** Multi-char operators are lexed greedily (`::`, `->>`, `@>`, `||`, `<=`, `<>`, `!=`).
- **Punctuation.** `( ) , . ; [ ]` are punct tokens, except where `[` opens an identifier.
- **Errors.** An unterminated string, quoted identifier or comment throws `SqlLexError`.

```ts
export interface TableReference { name: string; schema?: string; alias?: string; quoted: boolean; start: number; end: number; }
export interface ColumnReference { name: string; qualifier?: string; quoted: boolean; start: number; end: number; }
export interface SqlAnalysis {
  dialect: SqlDialect;
  tokens: Token[];              // every token including whitespace/comments
  statements: Token[][];        // significant tokens per statement; empty statements dropped
  hasComments: boolean;
  operation: QueryOperation | null; // of statement 0; WITH and leading '(' resolved to the main statement
  tables: TableReference[];     // base tables anywhere (FROM, JOIN, comma lists, UPDATE, INSERT/SELECT INTO,
                                // DELETE FROM, USING, MERGE INTO), CTE names excluded, table functions excluded
  cteNames: string[];
  aliases: string[];            // table/derived/function aliases, select-list aliases (AS x and implicit),
                                // CTE and alias column lists, WINDOW names, ON CONFLICT "excluded"
  columns: ColumnReference[];   // qualified a.b (qualifier = the part before the column) and bare-word
                                // column candidates (see below)
  starQualifiers: string[];     // '' for bare *, otherwise the qualifier of t.*
  functions: string[];          // UPPERCASED names of called functions (word or quoted followed by '(')
  nestedStatements: { keyword: string; start: number }[]; // statement keyword right after '(' (DML in CTE/subquery)
}
export function analyzeSql(sql: string, dialect?: SqlDialect, options?: LexOptions): SqlAnalysis; // throws SqlLexError
export function significantTokens(tokens: Token[]): Token[];
export function splitStatements(tokens: Token[]): Token[][];
/** Index of the first token at paren depth 0 (relative to `from`) whose value is one of `words`. -1 if none. */
export function findTopLevel(tokens: Token[], words: string[], from?: number, to?: number): number;
```

**Bare-word column candidates.** A word or quoted token counts as a candidate only when all of these hold:
- It is not in `SQL_KEYWORDS` (which includes types, date parts, constants such as `TRUE` and `CURRENT_DATE`, and window and fetch words).
- It is not followed by `(` or `.`, and not preceded by `.`.
- It is not in a table position.
- It is not the alias being defined.
- It is not after `::`, `COLLATE`, or `USING` (without `(`).
- It is not the first argument of `EXTRACT` or the T-SQL `DATEADD`, `DATEDIFF`, `DATEPART` and `DATENAME` functions.
- Its name is not in `aliases`.

**Alias definitions:**
- The word after `AS`.
- A non-keyword word right after a table name, a `)`, or the end of an expression (another non-keyword word, a quoted identifier, a literal).
- The words in a parenthesized list right after an alias definition or CTE name.

### 5.2 Validator (token-based)

- **Lexing.** Lex with the configured dialect. For mysql, lex in both backslash modes and combine the findings. If lexing fails in either mode, return the error "Query contains dangerous patterns: ambiguous string escaping" (or a syntax error for genuinely unterminated input).
- **Multiple statements.** More than one non-empty statement gives "Multiple statements detected". On mssql, a statement keyword in a later position also counts, because T-SQL does not need `;`: `SELECT 1 DELETE FROM t`.
- **Pattern names.** Dangerous patterns keep their 0.0.1 names in the message: `EXEC`, `EXECUTE`, `xp_cmdshell`, `sp_executesql`, `UNION.*SELECT`, `--`, `/*`, `DROP`, `TRUNCATE`, `ALTER`, `CREATE`, `GRANT`, `REVOKE`. They are now matched against tokens, never substrings, so names, quoted identifiers and strings never match.
- **New patterns.**
  - `SELECT INTO`.
  - `INTO OUTFILE` / `INTO DUMPFILE`.
  - `FOR UPDATE` / `FOR SHARE` locking clauses.
  - `function <NAME>` for blocked functions, with `blockedFunctions` and `allowedFunctions` overrides and prefix patterns.
  - `statement <KW>` for a statement keyword at a nested statement start that `allowedOperations` does not allow (for example a writable CTE).
  - `system table <name>` for `pg_shadow`, `pg_authid`, `pg_user_mapping(s)`, `mysql.user`, `sys.sql_logins` and `sys.syslogins`.
- **Comments.** A comment token in a query given straight to `validate()` is still reported as `--`, `/*` or `#`.
- **UNION.** Blocked unless `allowUnion`.
- **Operation.** Detected from tokens: CTEs resolve to the main statement, and leading `(` is skipped. Unknown statements give "Could not determine query operation".
- **Tables.** `allowedTables` is compared case-insensitively against every table reference. `schema.table` matches an entry for either `schema.table` or `table`. CTE names are excluded.
- **Restricted columns.**
  - An exact identifier match (bare, or the last part of a qualified name).
  - An entry written `table.column` matches only that table, via alias resolution.
  - With a schema: `*`, `t.*`, and `row_to_json`/`to_json`/`to_jsonb`/`json_agg`/`jsonb_agg`/`json_object`/`row` called with a table alias expand to that table's columns.
- **Sensitive columns.** Schema columns marked `sensitive` produce a warning, or an error when `enforceSensitiveColumns` is set.
- **LIMIT check.** Top-level only. The check is dialect-aware (`LIMIT n`, MySQL `LIMIT o, n`, `TOP n`, `FETCH FIRST n ROWS`). `LIMIT ALL` counts as no limit.

### 5.3 Sanitizer

- **Order.** Strip NUL bytes, then lex. Drop comment tokens (each replaced by a single space). Drop trailing `;` tokens and the whitespace around them. Collapse whitespace outside string literals and quoted identifiers.
- **Lexing failure.** If lexing fails, fall back to the 0.0.1 behavior on the raw text, so the syntax check can report the problem.
- **`extractFromMarkdown`.**
  - Accepts ```` ``` ```` and `~~~` fences with any language tag, in any case, with or without a newline after the tag. A `sql`-tagged block is preferred.
  - Also strips a leading "sql" line or an `<sql>…</sql>` wrapper.
  - With no fence, the text is returned as is.
- **`validateSQLSyntax`.**
  - Token-based. Accepts SELECT, INSERT, UPDATE, DELETE and WITH, also after leading `(`.
  - Parentheses balance on punct tokens only.
  - Unterminated strings give "Unbalanced single quotes" or "Unbalanced double quotes" (the 0.0.1 messages).
- **`addLimitIfMissing(query, limit)`.**
  - Adds a limit only when the main statement has no top-level LIMIT, TOP or FETCH.
  - mssql: inserts `TOP n` after `SELECT [DISTINCT|ALL]`.
  - Otherwise appends ` LIMIT n`.
- **`enforceLimit(query, limit)`.** Same as `addLimitIfMissing`, but also lowers a larger top-level limit in place.

### 5.4 Row-level security

`addRowLevelSecurity(query, ctx)` keeps its signature.

- **Scope.** SELECT, UPDATE and DELETE, applied to the main statement and to each top-level UNION, INTERSECT or EXCEPT branch.
- **Column.** `rowLevelSecurityColumn`, default `user_id`.
- **Value.**
  - A finite number is inlined.
  - A string is single-quoted, with `'` doubled. On mysql, `\` is doubled too.
  - Any other value, or a string containing NUL, throws `TextToQueryError('…', 'SECURITY_VALIDATION_FAILED')`.
- **Duplicates.** Skipped only when the top-level WHERE is a pure AND-chain (no top-level OR) that already contains `[q.]col = <same value>`.
- **Placement.**
  - The filter goes before the first top-level GROUP, HAVING, WINDOW, ORDER, LIMIT, OFFSET, FETCH, FOR or RETURNING of the branch.
  - It goes inside the branch, never inside parentheses.
  - With an existing WHERE: ` AND col = v` is appended to it. The existing condition is wrapped in parentheses only if it has a top-level OR.
- **Qualification.** With more than one table in the branch's FROM, the filter is qualified with the alias (or name) of the first table that has the column according to the schema, else the first table.
- **Lexing failure** returns the query unchanged. Validation then rejects it.

### 5.5 Generator pipeline

```
system = renderSystemPrompt()   // cached per generator
user   = user context + <question>…</question>
loop attempt = 1 .. 1 + maxCorrectionAttempts:
  raw = provider.generateWithSystem(system, user [+ correction feedback])
  if raw is CANNOT_ANSWER -> throw INVALID_SQL_SYNTAX {cannotAnswer, reason}
  sql = sanitize(extractFromMarkdown(raw))
  syntax = validateSQLSyntax(sql)          -> on failure: correct or throw INVALID_SQL_SYNTAX
  issues = checkIdentifiers(sql, schema)   -> per identifierCheck mode: correct, warn or (strict) throw
apply RLS (same condition as 0.0.1), enforceLimit (add if configured; clamp to the effective max, default 1000)
validate(final sql) -> throw SECURITY_VALIDATION_FAILED (never retried: a different question must not be answered silently)
metadata: operation, tables (lowercased, deduped, as 0.0.1), complexity (token-based), attempts, unknownIdentifiers
```

**System prompt layout.** Static content comes first so it can be cached:
1. The role and rules.
2. The dialect rules (quoting, LIMIT or TOP, date functions).
3. The schema, rendered with identifiers quoted where the dialect needs it, plus native types, enum values, descriptions, PKs, FKs and sensitive markers.
4. The security constraints.
5. The examples.
6. `instructions`.

The user message carries the user context (inside delimiters, marked as data) and the question inside `<question>` tags.

## 6. Testing

- **Unit tests per module.** The lexer corpus includes 159 valid and 39 dangerous queries (taken from the research harness).
- **Differential tests against 0.0.1.** These use the devDependency `text-db-query-ai-legacy` (npm alias of 0.0.1). They check:
  - Every query the old validator accepted is accepted, except the listed dangerous ones.
  - Sanitize and limit outputs are equal on simple inputs.
  - The schema prompt is identical.
  - The export surface is a superset.
- **Integration tests.**
  - PGlite runs in-process for Postgres.
  - sqlite3 runs in-memory.
  - MySQL runs only when `MYSQL_URL` is set.
  - MSSQL uses a fake executor.
  - The Prisma schema parser is tested against fixture schemas.
- **Live LLM smoke tests** run only when `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` is set, and are skipped otherwise.
